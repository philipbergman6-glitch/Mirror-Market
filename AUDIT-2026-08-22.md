# Mirror Market full-spectrum audit — 2026-08-22

## 1. Verdict

**Overall grade: C.** Mirror Market is a serious, unusually self-critical market-data research product, but it is not close to a Bloomberg-terminal-class system for a physical soy trader. I would use it as a morning research map and exception list; I would not price, hedge, nominate, or mark a cargo from it without checking other screens. The single largest gap is not Python quality: the system lacks the executable physical-market substrate—firm bids/offers, licensed freight, contract-quality adjustments, counterparty terms, and authoritative settlements—from which a cargo value is actually made. Worse, two implemented paths can turn missing inputs into plausible numbers: partial OHLC bars are forward-filled, and dated local prices may use an earlier FX close. Its strongest achievement is epistemic structure: price-type vocabulary, same-session joins, explicit absence, private/public separation, source-specific traps, and promotion gates are much better than the overall grade suggests.

The claim under audit is explicit: a physical-soy-trader platform spanning the relevant venues and answering cargo value, cheapest movement, and repricing (`CLAUDE.md:7`: “**Bloomberg-terminal-style market intelligence platform for physical soy traders**”; `CLAUDE.md:7`: “deciding what a cargo is worth, where it moves cheapest, and who has repriced”). The code is a capable public-data intelligence dashboard plus a manual desk-workflow shell. It is not an execution-grade terminal.

## 2. Map of the system before grading

### 2.1 Graph-first architecture hypothesis

I used the existing `graphify-out` artifact as orientation only. Its 9,575-node/25,097-edge graph described not one pipeline but five interlocked systems:

1. a legacy dataframe ingestion and headline-site path;
2. a newer trust ledger and edition/promotion path;
3. futures, contract, options and physical-origin analytics;
4. private desk workflows for assumptions, opportunities, positions and clearing; and
5. a very large behavioral-test system.

The highest-degree concepts were `TrustRepository`, `ObservationRevision`, `NamedContract`, `ScraperShapeError`, `AssumptionSet`, `ContractQuote`, `DatasetContract` and `PriceType`. That became the inspection hypothesis; source code, not the graph, determined every conclusion below.

### 2.3 Ground-truth trace: one Brazil Paranaguá number

This is the actual fetch → clean → validate → store → analyze → render path for the public “AgRural (USD)” Paranaguá number:

1. **Fetch/parse.** `fetchers/agrural.py:16-31` identifies the SOJA table, date, location and `Compra` column; `fetchers/agrural.py:282-295` parses the price and converts BRL/60kg bag to BRL/MT. The source itself calls this a port “buy price” (`fetchers/agrural.py:4-7`), while the product labels it FOB. That FOB interpretation is inferred from trade convention, not a distinct upstream incoterm field.
2. **Validate.** Missing table, row, date or nonpositive price raises/returns a failed `FetchResult` (`fetchers/agrural.py:304-329`). The cleaner parses dates, coerces numeric price, and drops missing/nonpositive observations (`pipeline/clean.py:522-548`).
3. **Store before grade.** `_run_scraper_layer` saves rows before recency grading (`main.py:588-616`); `save_brazil_spot` renames `price_brl_mt` to `price_brl` and upserts `(Date, commodity)` (`pipeline/store.py:880-895`).
4. **Grade.** AgRural has no configured age budget, so every nonempty payload passes recency (`main.py:327-335`; `config.py:1551-1562`). The suite proves a 400-day-old quote is stamped success (`tests/test_layer_recency.py:567-578`).
5. **Read/analyze.** `read_brazil_spot` reads the table (`pipeline/query.py:271-273`). Brazil basis inner-joins the local price, CBOT close and BRL/USD on date (`analysis/spreads.py:202-230`); the dashboard selects AgRural as the primary basis source (`analysis/soy_analytics.py:991-1026`).
6. **Render.** The Brazil group emits `agrural_soy_usd`, basis, and the observation date (`app/sections.py:636-644`); the relative-value template prints the price/basis blocks and dates (`app/templates/sections/relative_value.html.j2:7-33`). The briefing FOB board uses the same date-aligned basis and publishes the converted spot level (`analysis/briefing/sections/fob_board.py:48-66`).

Ground-truth conclusion: the arithmetic is same-date and the raw local price is kept native, but the freshness grade is not safe and “FOB” is a product interpretation of an upstream `Compra` port quote. I could not independently verify the market convention or AgRural page because the live run had no network.

## 3. The five things that matter most

### 1. Critical — the cleaner fabricates closing prices and downstream signals

**Observed.** `clean_ohlcv` drops only rows where *all* OHLC fields are missing, then forward-fills every remaining column for up to three rows (`pipeline/clean.py:116-126`). The test explicitly says a row with missing `Close` but present O/H/L becomes the previous close, and RSI/MACD/daily change cannot distinguish it from a real bar (`tests/test_clean.py:207-247`). This contradicts “Nothing is invented” (`CLAUDE.md:42`).

**Failure scenario.** Provider input: D has real O/H/L and missing Close; D−1 Close is 1,100. Cleaner writes D Close=1,100; storage persists it; daily change becomes 0%, RSI and MACD consume it (`analysis/technical.py:72-89`; `analysis/technical.py:113-114`); dashboard/briefing show a plausible close and signal. A trader sees “no move” instead of “no close” and delays/reverses a hedge. The value is fabricated, not merely stale.

**Fix.** Never fill OHLC prices. Drop/quarantine any partial candle or preserve nullable fields and make close-dependent consumers refuse it. Keep limited forward-fill only for explicitly low-frequency macro series whose semantics allow carrying a published observation. Replace the current test with a refusal/quarantine test and an end-to-end assertion that no partial bar reaches `prices.Close` or a rendered metric.

### 2. Critical to the product claim — the cargo is built from missing/manual inputs, not a tradeable market

**Observed.** The repository itself states that ocean freight, elevation, port charges, financing and quality differentials are unavailable and must be manually entered (`data/reference/assumptions/README.md:13-23`); all but China duty/VAT ship empty, so a fresh clone's origin comparison is blocked (`data/reference/assumptions/README.md:105-116`). No source is settlement-proven (`pricing/semantics.py:240-243`), no layer carries a firm counterparty offer (`ARCHITECTURE.md:393-400`), and there is no options chain (`analysis/futures/options.py:3-17`).

**Failure scenario.** Input question: “October Paranaguá soy, 34.5% protein, to North China—which origin is cheapest and what is my hedge?” The system has an interpreted port assessment, delayed closes and public benchmark freight, but no live route freight, elevation, spec differential, firm offer, counterparty, laycan/terms or executable board settlement. Correct output is blocked/manual. If a user mistakes the research board for a cargo valuation, the omitted $/MT inputs dwarf the displayed ranking.

**Fix.** Narrow the product claim immediately to “public-data soy intelligence and desk decision support.” To earn the old claim, buy or integrate authoritative named-contract settlements, route/period dry-bulk assessments, physical bid/offer capture with counterparty and expiry, quality/spec schedules, and a governed assumptions/quotes workflow. Make “actionable” impossible unless every cargo term is live, owned and time-bounded.

### 3. High — local prices can be converted with a different day's FX close

**Observed.** The invariant requires “that row's own date's FX rate or renders blank” (`CLAUDE.md:47`). Instead, both origin and site readers query `Date <= price_date` and return the newest earlier rate (`analysis/origins/sources.py:239-262`; `app/block_builders.py:219-238`). Public price, ledger, spread, basis and crush builders call that fallback (`app/block_builders.py:354-382`; `app/block_builders.py:1102-1123`; `app/block_builders.py:1190-1218`; `app/block_builders.py:1528-1538`).

**Failure scenario.** A Brazilian price prints Tuesday; Tuesday BRL/USD is absent after an FX fetch failure; Monday's rate is selected. The basis still shares Tuesday for physical and CBOT, but the FX leg is Monday. The output is a plausible USD/MT and spread with no warning, attributing part of an FX move to physical basis. This is exactly the cross-day contamination the prose says is forbidden.

**Fix.** Make the default query exact-date (`Date = ?`). If a business decision allows previous-business-day FX, encode that as an explicit alignment policy, carry both dates into the result, label the substitution, cap the gap, and exclude it from “same-session” claims. Add end-to-end tests for a missing exact-date FX row on every public calculator.

### 4. High — “success” can mean frozen or incomplete market coverage

**Observed.** Any layer above a minimum floor receives success, even below the known catalog size (`main.py:457-488`); the test says this is intentional (`tests/test_layer_coverage.py:194-201`). The current weather snapshot is 23/24 and still success (`data/history/data_freshness.csv:31`). Separately, unlisted layers bypass recency entirely (`main.py:327-335`); the test stamps a 400-day-old AgRural quote success (`tests/test_layer_recency.py:567-578`). This contradicts “only a fully-answered, recent, complete fetch stamps `last_success`” (`CLAUDE.md:41`).

**Failure scenario.** One crop-region feed silently disappears while the other 23 answer; the masthead remains green. Or AgRural serves a frozen page for months; the daily fetch returns one valid-looking row and advances `last_success`. Brazil basis and origin pages then display that old physical price against newer board/FX data wherever a date join exists, or continue presenting the old quote as a live layer. The operator sees “success,” so no outage ticket is opened.

**Fix.** Split `healthy` from `usable`: only full catalog coverage and age-certified payloads stamp success; partial-but-usable should be `incomplete`. Add observation-age budgets for every dated daily/weekly source, especially AgRural, Gulf, CEPEA, MAGyP and forward curve using `observation_date`. Gate headline health and alerts on that stricter state.

### 5. High — technical signals are computed across contract-roll discontinuities

**Observed.** The project knows Yahoo front-month tickers silently switch contracts and create non-economic gaps (`LAYERS.md:108-110`). SMA, RSI, MACD, Bollinger and historical volatility compute directly on raw `Close` (`analysis/technical.py:21-46`; `analysis/technical.py:49-89`; `analysis/technical.py:118-161`; `analysis/technical.py:205-235`). Signals near an estimated roll are merely demoted; the underlying indicators remain contaminated (`LAYERS.md:112-121`).

**Failure scenario.** A roll gap crosses an MA or spikes volatility without the soy market moving. The alert is demoted only if an estimated calendar catches the provider's actual roll. If Yahoo rolls earlier/later, a false momentum/volatility signal is presented normally; a trader changes hedge timing for a contract-switch artifact.

**Fix.** Build a provider-observed roll map and a back-adjusted continuous series for returns/technicals, while preserving raw named-contract levels for basis and execution reference. Until then, suppress—not demote—close-derived technical signals across detected/uncertain roll windows and display the named contract behind every current level.

## 5. Full findings by dimension

### 5.1 Domain completeness — **D+**

**Critical, observed:** The platform cannot independently answer its primary landed-cargo question because freight, elevation, port, financing and quality inputs ship absent (`data/reference/assumptions/README.md:105-116`). The blocked state is honest, but honesty does not make the domain complete.

**Critical, observed:** It has no firm physical offers and no authoritative exchange settlements. The policy explicitly supports `FIRM_OFFER` from nothing (`ARCHITECTURE.md:393-400`), and `PROVEN_SETTLEMENT_SOURCES` is empty (`pricing/semantics.py:240-243`). This makes it a reference/assessment system, not an execution terminal.

**High, observed:** Geographic coverage is asymmetric. Europe has only weekly rapeseed physical and no crush/basis (`config.py:2139-2168`); South Africa lacks local crush/export basis (`config.py:2200-2209`); Nigeria has no price, crush or basis (`config.py:2230-2245`). “Every venue that matters” in the mission (`CLAUDE.md:7`) is therefore a navigation map, not comparable market depth.

**High, observed:** Derivatives depth is mostly an interface. Options are manual and modelled (`analysis/futures/options.py:3-21`); futures curves lack authoritative settlement and open interest (`pipeline/store.py:665-677`).

**Adversarial check:** I tried to count the origin/opportunity/workstation modules as domain completion. They are real and deep, but the code itself withholds outputs when manual inputs are absent. A class representing freight or an empty options section is architecture, not data coverage.

### 5.2 Data integrity & epistemics — **C-**

**Critical, observed:** Partial OHLC values are fabricated by forward-fill; see top finding 1 (`pipeline/clean.py:116-126`; `tests/test_clean.py:207-247`).

**High, observed:** Prior-date FX is silently substituted; see top finding 3 (`analysis/origins/sources.py:239-262`; `app/block_builders.py:219-238`).

**High, observed:** “Success” is not complete and not universally recent; see top finding 4 (`main.py:457-488`; `tests/test_layer_recency.py:567-578`). The docs are not merely aspirational here: `CLAUDE.md:41` states the opposite invariant.

**Medium, observed:** Unit conversion has at least three implementation sites, not two. The invariant says only `pipeline/units.py` and `Source.to_usd_mt` (`CLAUDE.md:47`), but origins restates the four conversions (`analysis/origins/sources.py:130-149`). Tests pin parity, which refutes an immediate numerical mismatch, but it does not refute the maintenance hazard.

**Positive, observed:** NULL semantics and history round trips are unusually careful. Import binds blanks according to NOT NULL constraints and rejects blank numeric fields (`pipeline/history.py:218-259`); export refuses empty/shrinking/column-dropping rewrites (`pipeline/history.py:326-387`). Save-first/grade-second is real on scraper paths (`main.py:588-616`), and non-success preserves the prior success timestamp (`pipeline/store.py:1230-1249`).

**Positive, observed:** Same-date price arithmetic is real in core basis and market spread paths. Brazil basis constructs one dataframe from the three indexed series and drops missing rows (`analysis/spreads.py:202-230`); ledger spreads search an exact common date and otherwise withhold (`app/block_builders.py:1102-1123`); crush uses the set intersection of all three leg dates (`app/block_builders.py:1165-1177`). The FX fallback is the exception that breaks the larger claim.

### 5.3 Architecture — **B-**

**High, observed:** A 30th/32nd source is a wide change: fetcher, schema, store, query and `main.py` are explicitly required (`ARCHITECTURE.md:507-515`), then production inventory, age/coverage catalogs, history persistence, latency classification, alerts and surface registry may also need edits. The layer is not a plugin-shaped deep module.

**Medium, observed:** The market registry contract is substantially held. Builders are generic over descriptors (`app/block_builders.py:8-26`), and searches found no per-slug behavioral branch in them. Adding a market page is documented as a registry-only edit (`ARCHITECTURE.md:515`). The remaining `if block_id ==` dispatch (`app/block_builders.py:2032-2037`) is block-kind behavior, not market drift.

**Medium, observed:** The `{state, reason, data}` envelope is universal for the new nine market blocks, not the entire system. `build_blocks` catches and emits the triplet (`app/block_builders.py:2010-2028`); legacy headline section builders such as `_brazil_groups` return lists of cards/groups (`app/sections.py:616-646`). `CLAUDE.md:58` overstates universality.

**Medium, observed:** Trust is a parallel migration, not the authoritative read path. The production workflow calls reconciliation in an observational job whose output nobody reads and whose failure is allowed (`.github/workflows/deploy-dashboard.yml:86-104`); the architecture says v1 remains default and switches per dataset (`ARCHITECTURE.md:423-425`). That duplicates concepts and explains the graph's cross-cutting trust communities.

**Low, observed:** The documented dependency diagram is stale: many fetchers import pipeline result types (`fetchers/agrural.py:66-69`), contradicting `ARCHITECTURE.md:468-470`. This is not intrinsically a bad dependency—shared result types belong below fetchers—but the document should show it.

The strongest stylistic signal is extreme issue-history narration embedded in production modules—for example the 55-line settlement module preamble (`fetchers/_settlement.py:1-55`) and long configuration incident chronicles (`config.py:1566-1590`). Runtime guards stop network and committed-history side effects (`tests/_guards.py:1-23`).

### 5.8 Performance & scale — **B**

**Observed:** Documented production time is 6m02 for the daily pipeline and 3.4–3.6s for 13-page generation (`LATENCY.md:83-89`); this audit's isolated render took 6.35s. Fast refresh exists because 15-year Yahoo pulls dominate cost (`config.py:151-163`). Current SQLite was ~40 MB and committed history ~5.6 MB, so current single-user scale is easy.

**Medium, observed:** Export is O(total retained snapshot history) every run: every table is selected, sorted, materialized, and fully rewritten (`pipeline/history.py:326-389`). At 10× history this increases runner memory, I/O, git diff work and merge-conflict exposure.

**Medium, observed:** Schema duplicates SQLite's primary-key unique indexes with explicit unique indexes “belt-and-suspenders” (`pipeline/schema.py:676-704`), increasing storage/write work for limited current benefit.

**Medium, observed:** Rendering avoids obvious N×market rereads with a shared connection/cache (`scripts/generate_site.py:397-414`; `app/block_builders.py:164-179`). This is a genuine scaling strength.

**Low/medium, inferred:** Plotly series are embedded in static HTML and page budgets are 1.5 MB/150 KB (`scripts/generate_site.py:65-74`). At 10× history, every unclipped chart/drilldown becomes a payload risk even if generation time remains acceptable. Budgets catch size but do not make the product fast.

The workstation does call the path guard (`scripts/generate_site.py:316-345`). A config regression could therefore put the private opportunity edition under `docs/`. The `.gitignore` convention would not prevent Pages upload. This is a concrete asymmetry, not a hypothetical generic concern.

**Medium, observed:** Jinja is configured with `autoescape=False` (`scripts/generate_site.py:92-93`), and templates intentionally mark chart HTML safe (`app/templates/sections/relative_value.html.j2:33`). Most public labels are config-controlled, which reduces exposure, but ingested/source or reference text that reaches a template can become HTML/script. **Positive, observed:** Secrets are environment variables and `.env` is ignored (`.gitignore:31-33`); workflow keys are passed through GitHub secrets (`.github/workflows/deploy-dashboard.yml:165-178`). I did not inspect GitHub secret values or repository history for prior leaks.

## 7. What the graph got right and wrong

### Right

- It immediately exposed that the repository is a federation of legacy ingestion/site, trust ledger, futures/origins, desk workflows and tests—not a simple 29-layer ETL. That prevented a directory-order audit from mistaking `main.py` for the whole architecture.
- High-degree nodes identified the real conceptual load: repository/revisions/contracts, assumptions, price semantics and scraper shape errors. Source inspection confirmed those are the deepest interfaces (`pricing/semantics.py:1-35`; `analysis/futures/privacy.py:1-27`; `pipeline/results.py` via the many fetcher imports exemplified at `fetchers/agrural.py:66-69`).
- Cross-directory communities correctly led to the trust/v1 parallel path and origins' duplicated conversion seam (`ARCHITECTURE.md:423-425`; `analysis/origins/sources.py:130-149`).
- Peripheral nodes highlighted dormant `__init__` files, direct CEPEA/old India adapters and optional cloud plumbing. The first category was not dead behavior; the latter two really are dormant (`main.py:884-904`; `LAYERS.md:44-49`).

### Wrong or misleading

- The graph suggested an exposure → positions → limits → exposure cycle. Source inspection showed the apparent back-edge is type-only (`analysis/futures/limits.py:28-31`), so there is no runtime import cycle. Static relation extraction overstates Python `TYPE_CHECKING` edges.
- Isolated package `__init__` nodes are not evidence of dead code; they are packaging structure.
- Its many inferred semantic edges and 278 small communities exaggerated fragmentation. Registry/config-driven dispatch—the project's main architectural mechanism—does not appear faithfully in ordinary call edges. `config.MARKETS` drives source/table/unit behavior (`app/markets.py:1-27`), while the graph cannot judge whether those descriptors are economically correct.
- It could not detect the highest-stakes defects: forward-filled closes, prior-date FX substitution, success floors, licencing gaps, or an FOB label inferred from a `Compra` port quote. Those required reading values and policies in source (`pipeline/clean.py:116-126`; `app/block_builders.py:219-238`; `fetchers/agrural.py:4-31`).

Net: trust the graph for orientation, hotspots and “where should I look”; do not trust it for dependency truth, dead-code verdicts, dynamic registry behavior or correctness.

## 9. Unverified

I do not know the following from this audit, and I have not guessed:

- **Live upstream correctness or availability.** Network access was unavailable; `main.py --fast` could not resolve Yahoo. Checking requires credentials, unrestricted network, captured raw artifacts and reconciliation against provider pages/APIs.
- **The current public GitHub Pages edition.** I rendered/smoked an isolated candidate and inspected tracked `docs/`; I did not fetch the deployed URL. Checking requires network access and comparing its manifest to committed freshness.
- **API-keyed layers and degraded fallbacks.** USDA, FRED, FAS, EIA, data.gov.in personal-key behavior and MARS were not exercised live. Checking requires secrets in an isolated non-publishing run.
- **Licensing/legal conclusions.** I observed code/docs decisions for AgRural redistribution, MATIF, JSE, AFEX, Platts/Baltic and public display; I am not legal counsel and did not verify current contracts or website terms.
- **Economic truth of source labels.** In particular, I could not verify that AgRural's Paranaguá `Compra` quote is properly called FOB (`fetchers/agrural.py:4-31`), nor that each public assessment is representative/actionable.
- **External numerical reference validation.** Conversion densities, crush yields, duties, Black-76 outputs, expiry rules and cargo cost formulas were not reconciled against exchange specifications, broker statements or settled trades. Tests show internal consistency only.
- **Holiday/session edge cases for every venue.** The yfinance guard was read and tested locally, but real DST transitions, exchange holidays, early closes and provider date labels need replay against captured live frames.
- **Private workflow with real client records.** Gitignored positions/options/clearing/opportunity files were not present; only code and synthetic tests were inspected. A privacy red-team requires seeded canary records and inspection of every generated artifact/log/cache.
- **Injection exploitability.** `autoescape=False` is observed; I did not construct a malicious upstream/reference payload across every page. A security test should seed `<script>` in every externally derived text field and assert escaped output/CSP.
- **Mobile browser UX and accessibility.** Desktop rendering and non-browser smoke were inspected. Mobile viewport, keyboard flow, screen readers, contrast and performance need browser/accessibility tooling.
- **Production alert delivery.** Workflows create issues by design, but I did not inspect Actions runs, issue notifications, repository settings, Pages permissions, cache retention or secret rotation.
- **Graph coverage gaps.** I did not deeply inspect every source parser, every one of 278 graph communities, trial scoring/metrics, every trust repository method, player-research provenance, each chart, every opportunity detector, or all 2,993 collected test cases. Representative and high-degree regions were inspected: orchestration/config, cleaning/storage/history, price semantics, origins/futures/privacy, site builders/promotion, workflows, latency and targeted tests. Those uninspected regions remain unverified, not silently passed.

## Audit stance and evidence labels

- **Observed** means directly read in source/artifact or executed in this workspace.
- **Inferred** means a consequence of observed code, with the inference named.
- **Assumed** would mean an unverified premise; no grade-setting finding above relies only on one.

Before retaining each adverse finding, I searched for its countermeasure. The fabricated close survived because the test deliberately requires it. The FX finding survived because exact-date language conflicts with two `<=` implementations and public call sites. The stale/incomplete finding survived because the tests explicitly certify both behaviors. The privacy grade improved after verifying the recursive payload and resolved-path guards; the graph cycle finding was killed after source showed `TYPE_CHECKING`. Where live data, rights, or domain truth could refute a claim, it is in **Unverified** rather than scored as fact.
