Audited state: branch `resource-india-brazil-legs` including uncommitted WIP (mandi + CONAB preços), flagged as WIP.
- **Report only** — no fixes applied in this audit.

## 3. Ranked findings

### Critical (wrong numbers a trader could act on)

- **F1 — Two different Brazil basis numbers on the same page.** `analysis/soy_analytics.py:1141,1178-1199` computes EM basis from *latest closes of three series on potentially different dates*, while `analysis/spreads.py:144-161` date-aligns correctly. Confirmed in `docs/index.html`: briefing "+38.0/MT" vs EM card "+34.4/MT". If a spot layer stalls a week, the EM "basis" silently mixes week-old spot with today's futures/FX. Same pattern for SAFEX and India. *Fix: route all EM basis math through the date-aligned join; print as-of dates.*
- **F2 — SAFEX "spot" is actually the most-active deferred contract.** `fetchers/safex.py:167-169,210-211` equates highest volume with "nearest" — live cross-check proves otherwise (Jul 31: picked DEC26 R8,250 over near AUG26 R8,100, ~2% off, contract identity shifts silently; contract label parsed but never stored). Plus `safex.py:213-216` defaults trade date to *today* when the feed carries only a time → a frozen page stamps fresh dates forever; and no `dayfirst=True` risks D/M-swap. *Fix: pick nearest contract by month code, store the contract label, hard-fail on undated rows.*
- **F2b — Notícias Agrícolas parse trusts cell position with no commodity/magnitude anchor.** `fetchers/noticias_agricolas.py:87-118`: only requires "cepea" somewhere in page text; a column reorder stores a %-change as a price (0.83 BRL/MT), a display-unit switch inflates 16.67×, a redirect to a corn page stores corn as soy. *Fix: require "soja" in title + plausibility band (60–300 R$/saca) raising `ScraperShapeError`.*

### Major — production availability

- **F4 — PSD and AgRural are dead in CI ("failed · never succeeded" on the live site):** GitHub runner IPs are blocked/unroutable for `apps.fas.usda.gov` and `agrural.com.br`; both work locally (verified 2026-08-07). PSD feeds stocks-to-use + the global supply section; AgRural is the Brazil-basis source *and* snapshot-only (each missed day is unrecoverable history). *Fix: fetch via a proxy/self-hosted runner, or a fallback source; at minimum alert loudly.*
- **F5 — Failed deploy = silently stale public page.** The 2026-08-06 Pages deploy timed out; no retry, no alert; site served Aug-5 data for ~2 days. *Fix: retry step + failure notification (email/issue) in `deploy-dashboard.yml`.*
- **F19 — AMS Table C port-flows parser broken by layout drift** (today: "port row has 6 numeric columns, expected 8", `fetchers/usda.py`). Honest hard-fail, but the feature is dead until updated.

### Major — silent-staleness class

- **F3 — "Success" certifies the fetch, not the data.** `main.py:181` + `pipeline/store.py:641-656` stamp `last_success` whenever frames are non-empty, with no recency check; `commodity_freshness` covers only 7 tables. A frozen upstream serves old data daily and stays green forever. **F3a**: `fetchers/worldbank.py:253-265` *detects* >100-day-stale data and still returns it — the documented GUID-rotation trap, shipped. *Fix: recency check in `_finalize_layer`; return `{}` on stale World Bank data.*
- **F13 — Masthead can claim "all layers fresh" beside sections showing "No data".** `scripts/generate_html.py:155-169` counts only `data_freshness`; confirmed contradiction in `docs/index.html` ("17/17 layers fresh" + "DATA HEALTH: 5 critical"). *Fix: fold health criticals into the masthead.*
- **F14 — Weather forecast rows mask fetcher death for ~a week.** `analysis/health.py:85-157` uses `MAX(Date)` including future-dated forecast rows; snapshot.py already filters `observed_only`, health doesn't.
- **F15 — No as-of dates on trader-facing numbers** (basis line, EM cards, forward curve, command center). Only `gulf_basis.py:49-51` does it right. The `freshness_items` sidebar is built but never rendered in the template.
- **F12 — Chronic false "STALE" warnings train the user to ignore alerts.** `analysis/health.py:34,132` applies a flat 5-day threshold to weekly COT (9 permanent warnings, confirmed in today's run — Jul-28 COT is the *correct* latest report) and monthly World Bank. `config.py:667-680` already has the right per-layer map; health.py doesn't use it.

### Major — integrity backbone

- **F9 — One bad re-fetch can permanently overwrite good history.** `pipeline/store.py:209-215` INSERT OR REPLACE + warn-only validation (`pipeline/clean.py:35-58`): a corrupted yfinance close replaces the good stored value; the warning scrolls by in CI. *Fix: quarantine >X% divergence from the stored value for the same PK (prices/currencies only).*
- **F10 — history.py `""`↔NULL round-trip can poison PKs (latent).** `pipeline/history.py:107` coerces `""`→NULL; for nullable PK columns each import then duplicates rows unboundedly; for `gulf_bids.delivery` (NOT NULL) it aborts the whole pipeline. Today's CSVs verified clean — fix before it bites.
- **F11 — Partial data commits before the outage floor is evaluated** (`main.py:219-222`): a 2/10-key run stores those 2, marks the layer failed, and cross-commodity analytics silently mix dates. **Superseded, not fixed (T21 #69, 2026-08-22.)** The proposed remedy — evaluate the floor before committing, so a below-floor run stores nothing — was reversed by #157 and #212, which made *save first, grade second* the rule on both the dict and scraper paths: a partial run's rows are true observations, and mandi and Gulf bids serve the current day only, so discarding them punches a permanent hole no later run can refill. The harm named here is closed downstream instead — every spread and crush inner-joins its legs on Date and drops any session where a leg is missing (`analysis/spreads.py:75,141,217`), so a half-populated layer cannot produce a cross-day number. What F11 was really protecting — a below-floor run must never stamp `last_success` — holds: it records `status='incomplete'` and enters `_HARD_FAILURES` (`main.py:_mark_incomplete`), pinned on both paths by `tests/test_layer_recency.py`.
- **F8 — Forward curve distorted at the front.** `fetchers/forward_curve.py:62` drops the current-month contract while it still trades (first ~half of every delivery month), and `:118-131` mixes per-leg observation dates (illiquid deferreds up to 5 days old) → phantom contango/backwardation after big moves.
- **F6 — Mandi WIP must re-validate returned records** (`fetchers/mandi.py:133-182`): data.gov.in silently ignores unknown filter params; a field rename would store an all-India, all-commodity median as MP soy. Plus **F7**: endpoint unreachable from this network — prove CI reachability before merge.
- **F16 — COT reliability**: retry tuple misses `URLError`/`BadZipFile` (`fetchers/cot.py:96`); a CFTC market rename silently empties a commodity (`:80,151`).
- **F17 — CONAB**: `errors="coerce"+fillna(0)` can zero Mato Grosso out of the national sum (`fetchers/conab.py:85-86`); `report_date=today` every run fabricates revision history (`:182-183`).
- **F18 — Gulf bids regex drops negative-basis rows** (`fetchers/gulf_bids.py:66-67`, no `-?`), and the briefing hardcodes `+` (`gulf_basis.py:19-22`).

### Minor (selected)

- Dashboard COT week-over-week is dead code — key mismatch `spec_net_chg` vs `spec_wow` (`soy_analytics.py:857` / `generate_html.py:742`).
- "1Y avg" label on ~1 month of AgRural history (`generate_html.py:628`).
- Seasonal dashboard headline shows the trend-conflated metric the module itself calls misleading (`generate_html.py:861-866` vs `seasonal.py:95-160`).
- WASDE Mar/Apr sub-header hardcode; USDA `(D)`/`(NA)` sentinels stored raw; EIA biodiesel-vs-renewable-diesel label; PSD unit-column fallback to "1000 MT" (cotton is in bales); `query.py:62` empty-string filter returns whole table; corn factor 39.368 vs 39.3683 (0.0008%); mandi WIP env var `DATA_GOV_IN_API_KEY` undocumented; `SAFEX_COMMODITIES` config codes are dead/misleading; briefing freshness ignores `status="failed"` (dashboard path handles it).
- Process: WIP branch modifies `data/history/brazil_spot_prices.csv`, which CI rewrites daily on main — rebase carefully.

Bottom line: the free/public backbone (USDA-family + FRED + EIA + CFTC + WB) is a genuine licensing moat — but the *prices themselves* (CBOT, CEPEA, SAFEX, AgRural) are the RED set. Before charging anyone: swap Open-Meteo to paid, land Agmarknet (already in WIP), get a CEPEA commercial license (they sell one), and budget for licensed CBOT delayed data (e.g., a CME-licensed vendor). AgRural and SAFEX likely need replacement or agreements.

## 6. Coverage gaps vs the global physical soy trader

Missing, roughly in order of value: **Argentina domestic** (Rosario FOB, crush industry, export-tax policy — the #3 exporter is absent below PSD level), **ocean freight** (Paranaguá/US-Gulf→China spreads drive origin switching), **China customs imports & crush margins** (DCE covers price, not flow), US barge freight/river logistics, farmer-selling-pace indicators, vessel lineups. The EM tilt (SAFEX/India/Nigeria) is a real differentiator once F2/F6 land.

## 7. Feasibility note: the ≤15min–1h ambition

- Today: fetch-time delay ~15 min ✓, but display latency = up to ~26h weekdays (cron 12:00 UTC, actual start ~14:10 due to GitHub scheduling lag) and ~72h over weekends, plus unbounded when a deploy fails (F5).
- Technically, hourly rebuilds during CME hours are cheap (public-repo Actions minutes are free; ~10 min/run) and would hit ≤1h without re-architecture. The static-HTML model holds.
- The real blocker is **licensing, not engineering**: redistributing intraday/delayed CME quotes to third parties requires a licensed feed regardless of refresh rate (§5). Recommended path: stay settlement-anchored daily for fundamentals (your traders' actual cadence), add hourly price refresh only when a licensed price source is in place.
